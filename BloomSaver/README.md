# BloomSaver — Glitter

BloomSaver is the standalone HAPPY JARZ / BLOOMCORE **Glitter laboratory**. The current design deliberately keeps the background simple and puts the complexity into one continuously generative particle field instead of cycling through canned screensaver modes.

## Run on Raspberry Pi

When using the split-app workflow:

```bash
cd ~/BloomSaver
python3 bloomsaver_pi.py
```

After pulling repository changes, refresh the standalone app snapshot first:

```bash
cd ~/BloomCircuit
git checkout main
git pull
./tools/split_pi_apps.sh
```

No npm or external Python packages are required.

## Current design

BloomSaver is now **Glitter-first**:

- no background visual-mode playlist
- no timed preset switching
- no Evolution-seconds loop
- no forced periodic style reset
- a simple randomized dark background fade
- one living Glitter simulation that keeps generating new motion and combinations

The goal is a small set of simple rules that can combine into a very large visual space.

## Glitter engine

Glitter is generated by moving emitters, attractors, repulsors, bursts, drift and field noise. Emitters and force points have their own movement and lifetimes, so the field keeps changing without replaying a fixed animation.

The control panel exposes:

- glitter count
- emitters
- attractors
- repulsors
- speed
- drift
- swirl
- field noise
- attraction
- repulsion
- burst chance
- trails
- glow
- twinkle
- minimum glitter size
- maximum glitter size up to **24**
- **symbol chance**
- glitter hue
- hue spread
- background fade speed
- background saturation
- background brightness

## Symbol glitter

Glitter particles can spawn as glowing symbols in addition to dots, diamonds, crosses, dashes and shards.

The built-in pool includes:

- ASCII punctuation
- letters and numbers
- arrows
- stars
- geometric symbols
- card suits
- music marks
- math symbols
- block characters
- box-drawing glyphs

Symbol particles use the same physics as the rest of the field: motion, attraction, repulsion, drift, twinkle, glow, spin and size.

## Background

The background intentionally stays simple. It slowly fades between randomized dark hues and acts as a canvas for Glitter rather than a second competing screensaver engine.

Background controls remain user-editable through fade speed, saturation and brightness.

## Match Jar Colors on Start

BloomSaver includes a persistent **MATCH JAR COLORS ON START** toggle.

When enabled and a HAPPY JARZ palette is available at launch:

1. the active Jar light-pattern palette seeds the Glitter hue
2. the palette color distance seeds Glitter hue spread
3. the background begins from the Jar palette
4. the background eases into BloomSaver's normal randomized fade over roughly 20 seconds
5. after startup, user slider edits remain completely free

This is a **startup handoff**, not a live lock. BloomSaver does not continuously overwrite user changes.

### Controller integration hook

The HAPPY JARZ controller can provide a palette directly with:

```javascript
window.BloomSaver.setJarPalette({
  name: "OCEAN",
  colors: ["#0066ff", "#00d8ff", "#6f4cff"]
});
```

The bridge also accepts RGB objects, hue values, `primary` / `secondary` / `accent` fields, `postMessage` palette events, supported globals, localStorage palette values, and startup URL color parameters.

The intended controller flow is:

```text
active HAPPY JARZ light pattern
        ↓
pattern palette
        ↓
BloomSaver startup colors
        ↓
user may freely customize from there
```

## Actions

- **Randomize** — generates a new Glitter configuration.
- **Mutate** — nudges the current Glitter configuration without replacing it with a preset.
- **Pause** — freezes the simulation.
- **Fullscreen** — toggles fullscreen.
- **Match Jar Colors on Start** — remembers whether a Jar palette should seed startup colors.

## Saved presets

Saved presets are user-created Glitter configurations stored in browser `localStorage`. They do not auto-cycle.

A saved preset controls the Glitter laboratory settings; it does not restore the old background-mode playlist.

## Keyboard

- `R` — randomize
- `M` — mutate
- `Space` — pause/resume
- `F` — fullscreen
- `H` — hide/show controls

The UI auto-hides after five seconds of inactivity and returns on interaction.

## Integration direction

BloomSaver is being developed independently so its visual system can be tuned quickly on the Pi. The intended HAPPY JARZ desktop integration is to embed this same Glitter engine into the controller and pass the currently active light pattern's palette into the startup hook.

The physical Jar and desktop screensaver should therefore feel related without being forced to run identical animation logic.
